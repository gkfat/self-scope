# 共用特質語彙草案：雙極軸（供審稿）

> 狀態：**草案，待審**（第 7 版：定案第 1、2 題與計費模式（單維度免費全內容＋1 點 AI 進階分析；多維度點數、含 AI）；第 6 版：併入你對第 3 至 27 題的回答（見「已決定」）；第 5 版：新增「資料層」——資料層保留足以支援分析的內容，報告只顯示其中一部分；第 4 版：新增「情境軸」——時間、對象、生活領域，說明特質如何在不同情境下產生影響，並併入單維度與多維度報告的結構）。這份文件提出「共用特質語彙層」：把八字、人類圖、塔羅、盧恩、星座、MBTI 等各系統各自的語彙，轉成同一組**成對的兩極**，來描述人的特質、個性與行為偏好。審過之後才會變成專案內的資料檔（進版控）與各系統的映射檔。

## 這一版相對於第 1 版的修正

第 1 版是 37 個**單端**的特質（例如「規劃與長遠布局」），這一版依你的評語改為：

1. **成對的兩極**：特質是一條軸的兩端（長遠規劃 ↔ 活在當下），一個人落在軸上的某個位置，而不是「有或沒有」某個標籤。共 28 條軸。
2. **各系統專屬的語彙原樣保留，作為事實**：報告裡仍然寫「日主甲木」「投射者」「隱者（逆位）」「Raidho」；背後再映射到共用的軸。
3. **價值在映射之後的分析**：先逐軸解釋、再合併，目標是給使用者「自己想不到的洞見」，而不是把各系統的話重述一遍。
4. **塔羅與盧恩也納入**：它們描述的是「當下的狀態」而不是穩定的特質，所以映射時要標示時效（見下）。

## 整體流程

```
各系統的原始結果（事實）            例：日主甲木、投射者、INTJ、今天抽到隱者
        │  保留原語彙，原樣呈現在報告裡
        ▼
映射：系統語彙 → 共用軸上的位置      例：隱者 → 獨處內向（偏）、審慎斟酌（偏），時效＝今天
        │  每一筆都記錄來源系統、原語彙、依據
        ▼
單一軸的解釋                        這條軸上，各來源怎麼說、彼此獨立嗎
        ▼
情境展開                            每條軸 × 時間（過去／現在／未來）× 對象 × 生活領域
        ▼
跨軸的合併與洞見                    軸與軸的組合、張力、盲區、當下與長期的對照
        ▼
報告（附待確認的假設）
```

## 設計原則

- **軸，不是標籤**：每條軸的兩端都有名稱、定義與「過度時的樣子」。兩端是**中性的偏好**，不是好與壞（兩端的名稱要審，避免一端聽起來比較好）。
- **兩種映射方式**：
  - *結構式*：系統本身就有明確的結構，直接用規則對應。例如 MBTI 的四個字母、人類圖的類型與權威與是否定義的中心、八字的五行與日主強弱。結構式映射**天然有成對的兩端**。
  - *關鍵字式*：系統的內容只有文字描述（星座、血型、生命靈數、瑪雅 Kin、塔羅、盧恩），就把內容裡的關鍵字歸到軸的某一端。
- **只記方向，不編造強度**：一筆映射記錄「偏向 A 端、偏向 B 端或中性」。只有系統本身提供強弱時（例如大五人格的分數）才另外記錄程度，不把文字解讀轉成百分比。
- **來源要獨立計算**：同一個系統裡反覆出現的同一個方向只算一個來源。不同系統都指向同一端，只代表「有多個系統這樣說」，**不代表可信度提高**——它們的理論不同，也不是獨立的科學證據。
- **穩定特質與當下狀態分開**：出生資料、測驗得到的是**穩定**特質；塔羅、盧恩、星座運勢的月亮宮位是**今天的狀態**，帶日期、不寫進穩定特質，只在分析時拿來和穩定特質對照。

### 發現的問題

1. **另一端幾乎沒有來源**：現有內容的關鍵字全是「優勢」的正面描述，所以 A 端（正面）資料多、B 端（對立）資料少。完全沒有來源的端點有 5 個：**沿用經驗、過程導向、審慎憂患、知足安穩、輕鬆分擔**；另有 3 個端點來源很少。這不是軸定義的問題，而是來源的問題。補法有兩種：一是同時從內容的「盲點」與「過度使用」文字取得對立端的資訊，二是讓這幾個端點主要由**結構式映射**提供（例如 MBTI 的 P 或人類圖未定義的中心）。
2. **八字的十神語句不是特質**：例如「「印」所代表的力量較容易順手運用」。這些是八字系統內的說法，應原樣呈現成事實，**不映射**（或另請八字專家決定十神如何對應到軸）。
3. **人類圖的內容在程式常數裡**（類型、權威、人生角色、通道、閘門），不是 `fixedContents`，需要另外定義映射的粒度。
4. **有些軸彼此很近**（例如 B1、B4、B5 都和「彈性」有關，D1 與 A1 都涉及理性與感性），28 條可能偏多。

## 情境軸：特質在哪裡發生作用

**特質軸**回答「你是什麼樣的人」（28 條兩極軸）；**情境軸**回答「這個傾向在什麼時候、對誰、在哪類事情上產生影響」。兩者相乘（特質 × 情境）才是報告有用的地方，例如「承擔責任（E6 A 端）× 家人 × 未來」。

情境軸**不是兩極**，而是三份清單；任何一個特質端點都可以放到任何情境值上去看：

| 情境軸 | 值（提案） | 要回答的問題 |
|---|---|---|
| 時間 | 過去、現在、未來 | 這個傾向可能怎麼形塑你一路走來的樣子、現在如何出現、之後可能帶來什麼 |
| 對象 | 自己、伴侶、家人、朋友、工作夥伴、群體（社群與初識的人） | 對誰影響最明顯，對不同對象有沒有落差 |
| 生活領域 | 人際互動、自我成長、工作、娛樂、興趣發展、待人處事；候選：決策與選擇、情緒與壓力、生活節奏、學習 | 在哪類事情上最有感 |

「包括但不限於」：上表在你列的項目之外，加了**朋友**（對象）和四個**候選領域**，是否保留見「待你決定」。

**重疊要處理**：你列的生活層面裡有「人際關係」，它和「對象」軸幾乎重疊（伴侶、家人、朋友、夥伴本來就是人際關係）。建議領域裡的「人際關係」改名為「人際互動」，專指溝通與相處的風格，而「對誰」交給對象軸。

### 時間軸的規則

「過去、現在、未來」最容易寫成斷言或預言，所以先訂規則：

- **過去**：只能寫成「可能」與「你是否曾…」的假設，**不得斷言使用者的經歷**；每一則附一個確認問題。
- **現在**：描述這個傾向在日常中怎麼出現；若今天有塔羅、盧恩或星座運勢，與之對照。
- **未來**：只談**傾向**與**可以準備的方向**，寫成「若不調整，可能…；可以提早…」。**不預測具體事件**，不談健康、法律、財務建議。
- **系統自己的時間事實，要和本系統的時間解讀分開**：

| 系統 | 系統自己有時間結構嗎 | 本系統的做法 |
|---|---|---|
| 八字 | 有：大運（每十年一段，可分過去、目前、下一段）與流年 | 可作為「過去、現在、未來」的依據，並標「依八字大運」 |
| 生命靈數 | 有：流年數（每年一個） | 可作為「現在」的依據，標「依生命靈數流年」 |
| 星座／星盤 | 本命盤沒有；行運（今天的星空對本命盤）暫緩 | 只有反思式解讀 |
| 人類圖、MBTI、瑪雅 Kin、血型 | 沒有 | 只有反思式解讀，要標明「這是依特質作的推測，不是該系統的說法」 |
| 塔羅、盧恩、星座運勢 | 只有「今天」 | 只用在「現在」的對照 |

### 怎麼產生：特質端點 × 情境值的片段

- **預寫片段的鍵是（軸、端點、情境值）**，每一段是一句話。規模：56 個端點 × 15 個情境值（時間 3、對象 6、領域 6）約 **840 句**，每句約 30 至 50 字。這個量可行（由我起草、你審），但**不必全部填滿**：有些組合沒有意義（例如「自行判斷 × 群體 × 過去」）就留空，只要求每個端點在對象與領域上各有足夠的覆蓋。
- 分期：先寫**對象**（336 句），再寫**領域**（336 句）；**時間**用一套「過去、現在、未來」的**句型模板**套在同一批片段上，只補少量專屬片段（約 168 句以內）。
- 報告裡怎麼用：第 3 區挑出的 3 至 5 個面向，每個展開成一張**影響地圖**，三排（時間、對象、領域），每格一句。**全部格子都顯示**（決策 21）；沒有來源支持的格子留空，不顯示。
- 單維度免費版用預寫片段，內容全部提供；使用者可花 1 點數取得 AI 進階分析（針對這個人整合改寫）。多維度本來就收點數，AI 解讀包含在內。

| 時間：現在 | 日常裡傾向主動接下沒人認領的事。 |
| 時間：未來 | 若一直不調整，可能累積疲憊；可以提早練習把事情分出去。 |
| 對象：自己 | 對自己要求高，不太允許自己鬆手。 |
| 對象：伴侶 | 傾向自己扛，較少開口求助，對方可能不知道你需要什麼。 |
| 對象：家人 | 容易成為被依賴的角色。 |
| 對象：工作夥伴 | 可靠，但不太容易把工作放手交出去。 |
| 領域：工作 | 容易被交付更多責任。 |
| 領域：自我成長 | 學會「求助」可能是這個傾向最值得練習的一課。 |

## 洞見：分析層要做什麼

只找「共同」與「衝突」不夠，因為使用者自己也看得出來。有價值的是下面這幾種，每一種都可以由**程式依規則先找出候選**，再交給 AI 用個人化的語氣解釋，並附上「待確認的假設」：

| 洞見種類 | 說明 | 示例 |
|---|---|---|
| 收斂 | 不同理論的系統指向同一端 | 「兩個完全不同的系統都指向『長遠規劃』」（不宣稱可信度加倍） |
| 張力 | 同一個人在相關的軸上，不同來源指向相反端 | 「你的規劃偏好強，但今天的狀態偏隨興」 |
| 軸間交互 | 兩三條軸的**組合**產生單軸看不出的樣子 | 承擔責任（E6 A）＋獨處內向（D4 B）＋付出照顧（D2 A）：傾向用「默默扛起」來關心人，而不是開口求助，代價是別人不知道你需要什麼 |
| 盲區 | 所有來源都偏同一端，另一端沒有任何資料 | 「所有來源都偏向事先規劃，沒有人描述你在計畫被打亂時的樣子，那可能是你最吃力的地方」 |
| 情境差異 | 同一條軸在不同領域的位置不同 | 「工作上偏果斷，感情裡偏審慎」 |
| 對象落差 | 同一個傾向對不同的對象表現不同 | 「你對自己很寬容，對伴侶卻很苛求」「對工作夥伴很可靠，對家人卻很少說出需要」 |
| 時間延伸 | 同一個傾向在過去、現在、未來的角色改變 | 「這個傾向在過去讓你被信任，未來可能變成成本」（寫成假設，附確認問題） |
| 當下對照 | 今天的狀態和穩定特質對照 | 「你本來就偏獨處，今天的隱者呼應這一面，今天可以不必勉強社交」 |

其中「軸間交互」需要一份人工審稿過的**組合規則庫**（我建議約 30–60 條，由我先提案、你審），這是整個系統最有價值、也最需要品質控管的部分。

## 報告結構

### 一條貫穿所有報告的原則：從事實走到推論

每一份報告，不論單維度或多維度，都依同一個順序，**先事實、後推論**：

1. **位置結論**：使用者在這個系統裡的最終位置（例如「太陽天蠍座」「日主甲木」）。
2. **系統的事實與解讀**：該系統用自己的語彙算出的事實（五行、用神、四柱…），以及依這個系統的說法所作的解讀。
3. **本系統的歸納**：把上面的事實映射到共用的軸，歸納出幾個有助於自我探索的面向，並展開成**影響地圖**（在時間、對象、生活領域上各有什麼影響）。
4. **建議與反思**：由歸納的面向導出的小練習與問題。
5. **依據與限制**：系統性質、計算依據、版本與限制。

三條規則，讓「事實」與「推論」不混在一起：

- 第 1、2 區只放**系統自己的說法與可驗證的計算**，用原語彙；每一段解讀標明「依○○傳統／規則」。
- 第 3 區的每一條推論都必須**引用第 2 區的具體事實**，並標明來源（哪個系統的哪個原語彙）；同時標示這條推論是**規則推導**還是 **AI 推論**。
- 第 4 區由第 3 區導出，不憑空出現；證據不足的地方寫成**待確認的假設**，不寫成結論。

幾個重要的設計意涵：

- **第 1 至 3 區完全由規則產生，不用 AI**，所以任何維度數量都成本低、即時、可重現；**計費一律用點數**（決策 13），不再有免費的多維度報告。
- 目前「現成內容」靠預先寫好的 **14320 種組合摘要**（星座、MBTI、血型、生命靈數）；新的結構用「軸」組裝，**不需要為每個組合預寫**，維度再多也不會組合爆炸。這 14320 筆日後可以考慮退場（先不動，列為待你決定）。
- AI 的角色收斂為：**針對這個人，把規則找出的洞見與面向用個人化的語氣寫出來**，不再負責「自己找關聯」，這也讓 AI 的輸出更容易稽核。
- 每一區都標明資料性質：**事實**、**規則推導**、**AI 推論**、**待確認**，使用者看得出哪些是系統說的、哪些是我們推出來的。

## 資料層：保留足以支援分析的內容

**原則：報告不必顯示所有關係，但資料層要保留足以支援分析的內容。** 資料層 ⊇ 報告顯示的內容。理由：顯示可以日後再調整，但沒存下來的依據（規則版本、原始分數、精確位置）日後無法補回，也就無法追溯、重算或修正某個結論。

| 層 | 內容 | 對應本文 | 現況 |
|---|---|---|---|
| 1 位置結論 | 報告的快速摘要（「太陽天蠍座」「INTJ」「投射者」） | 報告第 1 區 | 有 |

### 分析報告不等於事實清單

事實項目回答「這個系統算出了什麼」；分析報告要回答下面六件事。**目前的報告結構已經涵蓋，不需要改版型**，只是第 5、6 點要明確標出來：

| 分析報告要回答 | 在我們的報告裡 |
|---|---|
| 這些結果在該系統中如何解讀 | 第 2 區 |
| 哪些特質或主題是核心 | 第 3 區（歸納的面向） |
| 有哪些優勢、盲點或可能過度使用的傾向 | 軸端點的「過度」說明（A 過度、B 過度） |
| 這些解讀可對應哪些生活情境 | 影響地圖 |
| 哪些結果彼此一致、互補或存在張力 | 洞見（多維度；**「張力」要明確寫出**，不只寫一致） |
| 哪些部分需要使用者回饋才能進一步確認 | 確認問題（只顯示，答案不存） |

### 四類內容分開標記

快照裡的每一段都標一個**種類**，讓跨維度報告能追溯每個結論的來源，也不會因為多套系統說了相似的話，就誤以為已被多次科學驗證（沿用前面「來源要獨立」的規則）：

| 種類 | 說明 | 例 |
|---|---|---|
| 事實 | 系統算出的結果與可驗證的計算 | 「日主甲木」「Kin 207」 |
| 系統解讀 | 依該系統傳統所作的解釋，不是本系統的主張 | 「依八字傳統，甲木…」 |
| AI 綜合推論 | 規則或 AI 把多個事實映射到特質軸所作的歸納 | 「傾向自行判斷」 |
| 使用者自述 | 使用者的回饋與例子 | 「這個很像我」 |

現有 AI 詳細報告已有 `evidenceKind`（OBSERVED、INFERRED），可以沿用並擴充成四類，不必另起一套。

### 這些決定帶出的後果

- **片段規模增加**：情境值由 15 個變成約 23 個（時間 3、對象 10、領域 10），56 個端點 × 23 ≈ **1,290 格**（原估 840）。仍不必全部填滿，分期不變：對象約 560 句、領域約 560 句、時間用模板。

- **多維度全付費後**：專案在測試開發階段，舊資料可清除、不考慮舊結構，14320 組合摘要與舊多維度 AI 報告由新報告取代，不並存。
- **單維度的「AI 進階分析」**：1 點數，對象是單一系統的報告；與現有 AI 詳細報告（`detailedReports`）與 `multiDimensionPricing` 的關係需在設計 change 時釐清（取代、並存或改名）。
