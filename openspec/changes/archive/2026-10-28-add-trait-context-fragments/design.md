## Context

- 草案規模：56 個端點 × 情境值；情境值已決定對象 10、領域 10、時間 3（共 23）。上限約 1,290 格，不必填滿。
- 時間軸規則（已決定）：過去只寫成假設並附確認問題；未來只談傾向與可準備的方向；不預測事件；不談健康、法律、財務。系統自己的時間事實（八字大運流年、生命靈數流年）屬報告 change，不在片段內。
- 使用者回饋層已決定不做：確認問題只顯示，不存答案。

## Goals / Non-Goals

**Goals:** 可驗證、可分期的片段資料；措辭規則可機器檢查。
**Non-Goals:** 組裝、顯示、AI 改寫。

## Decisions

### D1：片段以 `Record<'<端點ID>|<情境值ID>', Fragment>` 存放
`Fragment = { text, confirmQuestion? }`；缺鍵就是沒有片段，取用函式回傳 null，不從相近組合補。理由：寧可留白也不填入無來源的話。

### D2：時間值用模板，不逐一寫滿
時間（3 值）以句型模板套在對象或領域片段上，模板放在同一資料檔；只有確實需要專屬說法的才補專屬片段（上限約 168 句）。理由：避免 56 × 3 的重複內容。

### D3：措辭檢查用「必要條件 + 禁用清單」
- 過去：`confirmQuestion` 必填，且文字含假設語氣（如「可能」「也許」）。
- 未來：不得含事件性斷言（禁用清單，如「將會發生」「一定會」「必定」），須含傾向語氣。
- 全部：禁用清單含醫療、法律、財務用語。
禁用清單放資料檔、版本化，可擴充。這是機器能做的最低門檻，**內容正確性仍靠你審**。

### D4：覆蓋要求分期、可調
初始：每個端點在對象值中至少有 3 個片段，領域值中至少 3 個。數字為常數，測試依期別放寬或收緊。

### D5：版本
`FRAGMENT_VERSION`，內容改動即提高，進快照與 basis。

## Risks / Trade-offs

- **[內容量大、品質不一]** → 分批起草、你分批審；驗證只擋格式與措辭。
- **[禁用清單不可能窮盡]** → 清單可擴充；審稿是最後一道。
- **[留白的格子在「全部顯示」下顯示空洞]** → 報告 change 規定無片段的格子不顯示，不填補。
