## Context

目前每份多維度報告頁由「維度組成卡片 + 報告內容」構成。報告內容（現成內容）是事先組好的長文字；其中的「同向或拉扯」分析，是由暫存區的 Python 腳本（`insight.py`）根據下列規則產生：星座、血型、MBTI、生命靈數各自在三條軸線（能量方向、行事節奏、判斷重心）上有 +1／0／−1 的傾向；一條軸線上若各維度同向就是「同向」，有人反向就是「拉扯」（點名誰把你拉向哪邊）。這套規則與文字目前**不在專案內**，只存在於產生內容的腳本裡。

## Goals / Non-Goals

**Goals:**
- 報告頁最上方有一張四段式總覽：共同特質、不同觀點、值得探索的問題、下一步。
- 總覽在讀取時由規則產生：不增加儲存、不呼叫 AI，現成內容與 AI 報告都適用。
- 規則與文字有單一來源，放在專案內並有測試。

**Non-Goals:**
- 重新產生既有 1.4 萬筆內容、把人類圖或大五納入比較、AI 個人化總覽。

## Decisions

### 1. 規則與文字放成一份 JSON 資料，邏輯用 TypeScript 純函式

`shared/constants/crossInsightData.json` 存：各星座、MBTI 字母、血型、生命靈數的三軸傾向；同向文字（6 組）、拉扯文字（6 組）、平手文字（3 組）、各軸的反思問題、每個生命靈數的每週練習等。`shared/utils/crossInsight.ts` 讀取資料並輸出總覽。

- 為什麼用 JSON：資料與邏輯分開，文字修改不需要動程式；也方便未來的內容產生腳本直接讀同一份，避免兩邊文字分岐。
- 資料的初版直接由暫存區的 Python 表格匯出，確保與現有組合內容用的是同一批文字。
- 替代方案：把表格直接寫進 TypeScript。可行，但文字很多（約 100 段），放進程式碼不利於日後審稿與修改。

### 2. 總覽的產生邏輯（純函式，可測試）

輸入：組合（星座、MBTI、血型、生命靈數，每個可為空；人類圖忽略）。
1. 取出有傾向的維度作為「投票者」；少於 2 個就回傳空（不顯示總覽）。
2. 對三條軸線各自判定：同向（所有非零投票同方向）、拉扯（多數 vs 少數，點名少數者）、平手（正負各半）、無傾向（全為 0，略過）。
3. 輸出四段：
   - 共同特質 ← 同向的軸線（沒有就寫「各維度看的重點不同，沒有特別一致的地方」）
   - 不同觀點 ← 拉扯與平手的軸線，每條一句，說明誰與誰不同
   - 值得探索的問題 ← 取最主要一條拉扯軸線的反思問題與「內心拉扯」描述；沒有拉扯時取同向軸線的「過度時的風險」
   - 下一步 ← 一個每週練習（取最主要軸線的建議，加上生命靈數的小習慣，若有）

### 3. 呈現

`ReportOverview.vue`：卡片，四個區塊各有圖示與標題，順序固定；色彩沿用報告頁的維度顏色。位置在「維度組成」卡片之後、報告內容之前。窄螢幕下堆疊。沒有結果（少於 2 個可比較維度）時整張卡片不渲染。

### 4. 現成內容與 AI 報告一視同仁

總覽只看組合，不看報告內文，所以不需要後端支援。含人類圖的 AI 報告中，若星座、血型、MBTI 或生命靈數至少有 2 個，也顯示總覽；人類圖本身暫不參與。

## Risks / Trade-offs

- [規則資料與既有 1.4 萬筆內容的文字分岐] → 初版直接由同一批表格匯出；之後修改文字時，需要決定要不要重新產生內容（列入未解問題）。
- [總覽與下方內文講的是同一件事，感覺重複] → 總覽只放「結論式」的短句，內文維持細節；若使用者覺得重複，再考慮把內文折疊。
- [規則簡化：每個星座或血型只用 +1／0／−1 描述] → 文字用「傾向」語氣並附免責聲明；血型與星座本來就只是娛樂性的參考。
- [人類圖報告的總覽只涵蓋其他維度] → 在卡片說明中不特別強調；人類圖的比較另行研究。

## Migration Plan

1. 由暫存區表格匯出 `crossInsightData.json`，撰寫函式與測試。
2. 新增元件並放入報告頁。
3. 無資料遷移；回滾只需移除元件。

## Open Questions

- 修改規則文字後，是否要重新產生並匯入既有組合內容，讓兩邊一致？
- 人類圖各類型與通道的軸線傾向要如何定義？是否值得納入？
- 大五人格完成後，是否把連續分數作為更細緻的投票來源？
