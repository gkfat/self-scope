## Context

- 現況：各系統有固定內容與結果頁（`fixed-results` 路由與 `app/components`）；AI 詳細報告是多維度、付費、背景生成、失敗退點（`detailedReport.service.ts`，`maxDuration` 180s）。
- 已決定：單維度免費版內容全部提供；AI 進階分析 1 點；影響地圖全部顯示；確認問題只顯示；快照存全文；MBTI 為自製問卷需明標。
- 前置資料：`basis`（規則版本）、特質本體與映射、片段、快照、星盤宮位相位、人類圖解讀。

## Goals / Non-Goals

**Goals:** 一個通用的單維度報告組裝流程，各系統只需提供「位置結論」「事實項目」「映射輸入」；先事實後推論；全部可追溯。
**Non-Goals:** 多維度；新增系統；使用者回饋；片段與映射內容。

## Decisions

### D1：組裝是純函式管線，各系統提供 adapter
`SystemAdapter = { positionConclusion(), facts(), interpretations(), traitInputs(), natureLabel }`。管線把 adapter 的輸出依區塊順序組成報告，**第 3 區的每一條推論必須引用第 2 區的具體事實**（沒有引用則不產生）。理由：新增系統只寫 adapter；可單元測試。

### D2：影響地圖由映射結果與片段取用組成
由映射得到的端點，對每個情境值查片段；有片段才顯示（不填補）。全部顯示的版面細節（折疊、分頁籤、分組）在前端決定，不影響資料。

### D3：AI 進階分析是另一個動作，不改變免費內容
扣 1 點，背景產生，失敗退點，沿用既有的冪等鍵（`Idempotency-Key`）、品質檢查與 `waitUntil` 做法；輸入只含事實與規則找出的面向（不含自由文字）；輸出每段標 `AI 綜合推論` 並附依據，**寫入快照獨立的 `ai` 欄位，與規則產生的基本內容並存、不取代**（基本內容、版本與計算依據都不變；再次分析時只換 `ai`）。理由：重用已驗證的流程，降低風險；也讓「相同報告只存一份」只需比較基本內容，AI 分析不會讓報告變成另一份。

### D4：單維度與多維度的舊路徑由後續 change 移除
單維度 AI 進階分析使用新路由與快照；既有多維度 AI 報告與 `multiDimensionPricing` 由 `add-multi-dimension-report` 取代並移除。專案處於測試階段，不考慮舊資料與舊結構。

### D5：狀態系統（塔羅、盧恩、運勢）用精簡版報告
它們是「今天的狀態」，不映射到穩定特質（本體已規定），因此報告只含位置結論、事實與解讀、建議、依據與限制。

### D6：時間性內容的來源標示
八字大運流年、生命靈數流年數：標「依○○」並存入快照；其餘系統的時間解讀一律標「這是依特質作的推測，不是該系統的說法」，且過去只寫假設（片段已保證）。

## Risks / Trade-offs

- **[影響地圖全部顯示會很長]** → 版面分組折疊；資料層不受影響；若實際太長，可事後再決定預設展開數（版面決定，不改資料）。
- **[各系統事實的資料不足]** → 前置 change 補齊；缺資料時該區塊明確標示缺少，不猜。
- **[AI 輸出品質與成本]** → 沿用既有品質檢查與用量紀錄（`aiUsageRecords`）；1 點定價是否覆蓋成本需以實測用量確認（見 Open Questions）。
- **[分期上線期間，已切換與未切換的系統並存]** → 以系統為單位切換、逐一驗收；每個系統切換後即移除該系統的舊結果頁。
