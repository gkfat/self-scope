## Context

- 草案：`docs/trait-ontology-draft.md` 第 7 版。由固定內容關鍵字探勘得 320 個單維度關鍵字（星座 48、血型 16、MBTI 61、生命靈數 47、八字 164）；初步涵蓋率 96%（307／320）。
- 已決定（草案「已決定」）：28 軸與命名照提案；映射資料在專案內進版控；MBTI、人類圖（到通道）、八字用結構式；沒有來源的 5 個端點用結構式；八字十神語句不映射；塔羅、盧恩、運勢為狀態。
- 專案慣例：`shared/` 為前後端共用、zod schema 為契約、純函式易測；scripts 以 Node 內建 TypeScript 執行。

## Goals / Non-Goals

**Goals:** 可驗證的資料檔（軸、情境軸、映射）；每條映射有來源與方法；覆蓋率可檢查；規則版本可追溯。
**Non-Goals:** 報告組裝、片段文字、AI 提示、UI。

## Decisions

### D1：資料用 TypeScript 檔（`as const` 加 zod 驗證），不用 JSON
理由：型別可推導端點 ID；版控 diff 清楚；與 `shared/constants/` 一致。替代：JSON／YAML + 載入器 → 無編譯期檢查；否決。

### D2：軸 ID 與端點 ID 為穩定字串，名稱可改
ID 如 `A1`、端點 `A1.A`／`A1.B`；顯示名稱改動不影響映射。ID 一經發布不重用。

### D3：映射條目結構 `{ system, term, axisEnd, method, weightless }`
`method` 為 `structural` 或 `keyword`；**不帶強度數字**（草案原則：不做信心或強度分數）。`term` 必須是該系統真實存在的原語彙（以該系統的列舉或常數驗證，不接受自由文字）。

### D4：「狀態」系統另標 `kind: 'state'`
塔羅、盧恩、運勢的條目標為狀態，載入器 MUST 拒絕把狀態條目放進穩定特質的映射檔，避免混用。

### D5：來源獨立性以 `sourceGroup` 標記
同一傳統的系統共用一個來源群組（例如多個西方占星衍生系統），驗證與報告可據此避免把「多套系統說了相似的話」當成多次驗證。群組定義在 ontology 內。

### D6：覆蓋率檢查是測試與 script 兩用
覆蓋率下限（初始 90%，現況 96%）寫進測試，低於下限即失敗；script 輸出各系統與各端點的報表供審閱。

### D7：版本
`ONTOLOGY_VERSION`、`MAPPING_VERSION` 兩個字串常數，任何軸、端點或映射內容改動即提高，並進 `add-report-data-layer` 的 basis／快照。

## Risks / Trade-offs

- **[映射主觀性高]** → 每條映射有 `method` 與可審查的來源；你審閱內容；八字、MBTI、人類圖優先用結構式降低主觀。
- **[28 條軸日後要調整]** → ID 穩定、版本化；調整時走新 change。
- **[關鍵字映射可能漏掉語意]** → 覆蓋率報表列出未映射的關鍵字供人工補。
- **[映射檔量大（數百條）]** → 分系統分批起草與審閱（tasks 已拆）。
