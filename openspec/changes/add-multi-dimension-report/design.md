## Context

- 現況：多維度價格 = 各維度基本價之和 × 維度數權重 × 1.5（含生成）或 ×1（寫好的摘要），上限 30（`multiDimensionCost`）；寫好的摘要只涵蓋星座、MBTI、血型、生命靈數（14320 組合）；含人類圖、八字或瑪雅 Kin 的選擇走 AI 生成。
- 已決定：多維度基本需點數、AI 解讀費用含在內；取代舊路徑（測試階段，不考慮舊資料）；不顯示信心數字；同源不算多次驗證；塔羅、盧恩、運勢只做當下對照；影響地圖全部顯示。
- 前置：映射（含 `sourceGroup`）、片段、快照、單維度報告管線。

## Goals / Non-Goals

**Goals:** 規則先找洞見候選、AI 只負責「針對這個人改寫」，使輸出可稽核；任意維度數不產生組合爆炸。
**Non-Goals:** 新增系統；使用者回饋；舊資料的相容與遷移。

## Decisions

### D1：AI 的角色收斂為改寫，不自己找關聯
規則找出洞見候選（含來源事實），AI 依候選改寫成個人化文字；AI 輸出每段必須引用候選 ID，找不到引用的段落被品質檢查拒絕。理由：稽核容易、避免憑空關聯。

### D2：洞見規則結構
`{ id, type, when, requiresIndependentSources, template }`；`type` 為收斂、張力、軸間交互、盲區、情境差異、對象落差、時間延伸；`when` 為對軸端點與來源條件的宣告式描述（非任意程式碼）。規則版本化（`INSIGHT_RULES_VERSION`）。

### D3：獨立性判斷用 `sourceGroup`
收斂類洞見只有在支持它的來源屬於**至少兩個不同 `sourceGroup`** 時才標「多個獨立來源」；否則標「同源」。不產生數字。

### D4：計費
新結構報告一律視為「含 AI」，價格公式沿用 `multiDimensionCost` 的維度價與維度數權重並套用含生成的權重，上限不變。既有寫好的摘要路徑（免費組合摘要的價目分支）隨舊路徑一併移除。**最終價目待你決定**（Open Questions）。

### D5：背景生成與退點沿用既有流程
扣點、冪等鍵、`waitUntil`、品質檢查、失敗退點、`aiUsageRecords` 沿用 `detailedReport.service.ts` 的模式，不另起一套。

### D7：同一個系統內的矛盾與跨系統的矛盾要分開處理
映射沒有強度，所以同一個系統的結果可能同時指向同一條軸的相反兩端（例如人類圖的太陽神經叢有定義指向情緒細膩易感、根部有定義指向情緒穩定抽離）。這是該系統的特徵，不是映射錯誤，報告 MUST NOT 擇一、平均或當成多個獨立來源。規則庫要把它標為「系統內張力」，與「不同來源之間的張力」分開，且同一 `sourceGroup` 內的重複不計為多個來源。

### D6：多維度的影響地圖整合各系統
同一格由多個系統支持時合併呈現並列出各支持來源；來源衝突時列為「張力」洞見而不是擇一。

## Risks / Trade-offs

- **[規則庫主觀、數量大]** → 你逐條審；`when` 宣告式易於審閱與測試；每條規則附一個範例輸入輸出測試。
- **[AI 改寫偏離候選]** → 引用 ID 檢查與品質檢查；失敗退點。
- **[移除舊路徑時漏改相依處]** → 先以 grep 找出 `SummaryService`、`detailedReports` 與 `multiDimensionPricing` 的所有使用處，逐一改完並跑全測試；價目集中在 `multiDimensionPricing`。
- **[報告很長]** → 版面分組折疊，資料不刪減。
