## UC-001 以 Google 登入

- **Actor**：CTX-ACTOR-001
- **對應 Story**：STORY-001
- **對應 Requirement**：FR-001, FR-032

**Preconditions**

- 使用者未登入（含訪客）
- Firebase Auth 已啟用 Google provider

**Main Flow**

1. 使用者在 app 中選擇 Google 登入
2. 系統開啟 Google 登入視窗
3. 使用者完成 Google 授權
4. 前端取得 Firebase ID token 並送交後端 〔NFR-003〕
5. 後端驗證 ID token 並辨識帳號 〔NFR-001, NFR-003〕
6. 系統回傳登入成功並導向原頁面

**Alternate Flows**

- **使用者關閉或取消登入視窗**：保持訪客狀態並提示可再次登入
- **ID token 無效或過期**：後端回傳 401，前端重新取得 token 重試一次，仍失敗則提示重新登入
- **Google 或 Firebase Auth 服務失敗**：顯示明確錯誤，保持訪客狀態，不寫入任何資料

**Postconditions**

- 使用者已登入，後端可辨識其帳號
- 首次登入者另走 UC-002

## UC-002 首次登入建立帳號並領取贈點

- **Actor**：CTX-ACTOR-001
- **對應 Story**：STORY-002
- **對應 Requirement**：FR-001, FR-037

**Preconditions**

- 使用者首次以此 Google 帳號登入（後端查無對應帳號）

**Main Flow**

1. 後端驗證 ID token 後確認帳號不存在
2. 系統建立使用者帳號與點數帳戶 〔NFR-017〕
3. 系統檢查贈點紀錄（上次贈點未滿 3 個月者不發放），並一次性發放 3 點贈點、記錄贈點時間與異動 〔NFR-017〕
4. 系統告知使用者已獲得 3 點

**Alternate Flows**

- **並行或重送的首次登入請求**：贈點 MUST 僅發放一次，其餘請求回傳既有帳號
- **建立帳號或點數帳戶失敗**：整體回滾、不發放贈點，回傳明確錯誤，使用者可重試
- **帳號已存在**：略過贈點，視為一般登入
- **此 Google 帳號先前曾刪除帳號**：視為全新帳號：建立新的使用者與點數帳戶，不繼承任何歷史紀錄；若上次贈點未滿 3 個月則不再發放贈點（RULE-031）

**Postconditions**

- 帳號與點數帳戶存在，餘額 3 點，贈點僅一次

> 備註：贈點效期見 FR-042（長度待討論）

## UC-003 填寫生日、星座與選填資料

- **Actor**：CTX-ACTOR-001
- **對應 Story**：STORY-003
- **對應 Requirement**：FR-002

**Preconditions**

- 使用者開啟個人資料或測驗入口

**Main Flow**

1. 使用者輸入生日；系統帶入對應星座供確認 〔NFR-001〕
2. 使用者可選填血型（A/B/O/AB/不知道）
3. 使用者可選填 MBTI、出生時間與出生地點（出生地點從預設城市清單選擇）
4. 系統驗證必填欄位（生日、星座）並在後端驗證格式 〔NFR-001〕
5. 已登入者：系統儲存資料；訪客：以 session id 暫存於 Firestore，TTL 1 天，不與帳號關聯 〔NFR-005〕

**Alternate Flows**

- **必填欄位缺漏或格式無效**：標示錯誤並阻擋繼續
- **血型選「不知道」**：記錄為未知，後續分析不計入血型
- **訪客**：畫面明確提示未登入將不保留資料

**Postconditions**

- 個人資料可供單項結果、summary 與人類圖使用

> 備註：訪客資料不寫入 Firestore（FR-032）

## UC-004 取得單項免費結果（星座、血型）

- **Actor**：CTX-ACTOR-001
- **對應 Story**：STORY-004
- **對應 Requirement**：FR-040, FR-007, FR-002

**Preconditions**

- 已提供生日／星座，血型分析另需已選血型

**Main Flow**

1. 使用者選擇查看星座結果
2. 後端依生日／星座回傳固定結果內容 〔NFR-010, NFR-007〕
3. 使用者可選擇查看血型分析，後端回傳該血型固定內容
4. 系統顯示結果並附娛樂性免責說明 〔NFR-007〕

**Alternate Flows**

- **血型為「不知道」或未填**：不提供血型分析，提示可補填
- **結果內容讀取失敗**：回傳明確錯誤，不使用 AI 補足 〔NFR-011〕

**Postconditions**

- 使用者看到固定單項結果；系統不扣點、不儲存此結果

## UC-005 完成 MBTI 測驗

- **Actor**：CTX-ACTOR-001
- **對應 Story**：STORY-005
- **對應 Requirement**：FR-003, FR-004, FR-024, FR-040, FR-007

**Preconditions**

- 使用者開啟測驗清單

**Main Flow**

1. 系統顯示可用測驗清單，使用者選擇 MBTI 〔NFR-012〕
2. 後端回傳含版本的題目與選項
3. 使用者逐題作答；已告知時才記錄作答時間 〔NFR-005〕
4. 使用者送出作答，後端驗證並依評分規則計算 16 型 〔NFR-001〕
5. 系統顯示 MBTI 固定結果與免責說明 〔NFR-007〕
6. 已登入者：系統保存此次測驗版本、作答與結果；訪客：以 session id 暫存於 Firestore，TTL 1 天 〔NFR-005〕

**Alternate Flows**

- **作答不完整或選項無效**：後端拒絕並指出缺漏題目
- **測驗版本已更新**：以送出時的版本評分，記錄所用版本
- **訪客**：結果頁提示未登入將不保留，並提供登入入口（UC-006）
- **保存失敗**：仍顯示結果，提示保存失敗並可重試

**Postconditions**

- 使用者取得 MBTI 結果；登入者的測驗結果保存 3 個月

## UC-006 訪客登入並保存當次結果

- **Actor**：CTX-ACTOR-001
- **對應 Story**：STORY-006
- **對應 Requirement**：FR-032, FR-005, FR-001

**Preconditions**

- 訪客已完成測驗並看到結果
- 結果已以 session id 暫存於 Firestore（TTL 1 天）

**Main Flow**

1. 結果頁提示未登入將不保留，使用者選擇登入保存
2. 使用者完成 UC-001 登入
3. 後端依 session id 取出暫存結果並寫入該帳號 〔NFR-001, NFR-003〕
4. 系統確認已保存並顯示於個人中心

**Alternate Flows**

- **使用者拒絕登入**：不保存，暫存結果於 TTL 到期後自動清除
- **暫存結果已過期（超過 1 天）或 session 不存在**：提示結果已失效，引導重新測驗
- **登入後寫入失敗**：提示失敗並保留畫面結果供重試
- **重送造成重複寫入**：以當次結果冪等寫入，不產生重複紀錄

**Postconditions**

- 當次結果歸屬登入帳號，保存 3 個月；該 session 的暫存結果已清除

> 備註：暫存機制已定：session id + Firestore TTL 1 天（FR-032）

## UC-007 取得多維度分析報告

- **Actor**：CTX-ACTOR-001
- **對應 Story**：STORY-007
- **對應 Requirement**：FR-006, FR-007, FR-038, FR-041, FR-014, FR-042, FR-032, FR-040

**Preconditions**

- 使用者已登入
- 已提供星座與 MBTI（血型選填）

**Main Flow**

1. 使用者選擇取得多維度分析報告
2. 後端驗證登入身分 〔NFR-003〕
3. 後端依有無血型決定組合：星座+MBTI 或 星座+MBTI+血型（血型未知則用前者）
4. 後端檢查該會員是否已生成過此組合；若已生成則直接回傳已存 summary，不扣點 〔NFR-017〕
5. 否則後端檢查未過期點數餘額 ≥ 1 〔NFR-017〕
6. 後端原子地扣 1 點、記錄異動並保存該 summary 結果 〔NFR-017〕
7. 系統顯示 summary 與免責說明 〔NFR-007, NFR-010〕

**Alternate Flows**

- **訪客**：不可取得；提示登入（UC-001）
- **缺少 MBTI**：不提供 summary，引導完成 MBTI 或改看單項結果
- **點數不足或已過期**：拒絕並引導購買點數（UC-010）
- **並行重複請求**：僅扣一次點，其餘回傳已生成結果
- **讀取組合內容失敗**：不扣點，回傳明確錯誤 〔NFR-011〕

**Postconditions**

- 會員取得該組多維度分析報告並保存 3 個月；已扣 1 點（首次）；重複取得不再扣點

## UC-008 計算並檢視人類圖

- **Actor**：CTX-ACTOR-001
- **對應 Story**：STORY-008
- **對應 Requirement**：FR-036, FR-002

**Preconditions**

- 已提供生日、出生時間與出生地點

**Main Flow**

1. 使用者選擇查看人類圖
2. 後端驗證出生資料完整 〔NFR-001〕
3. 後端依規則計算並回傳固定結果：類型、能量中心、人生角色、內在權威、策略、定義與通道、閘門；已登入者儲存於帳號，訪客暫存於其 session（TTL 1 天）
4. 系統顯示結果並附娛樂與自我探索免責說明 〔NFR-007〕

**Alternate Flows**

- **未填出生時間或地點**：不產生人類圖，提示補填
- **出生地不在預設城市清單**：請改選最接近的城市
- **出生資料無效**：標示錯誤並拒絕計算
- **計算失敗**：回傳明確錯誤，不使用 AI 補足 〔NFR-011〕

**Postconditions**

- 使用者看到人類圖結果；已登入者的結果已儲存（保存 3 個月）；此結果為固定計算，不呼叫 AI

> 備註：單獨檢視不扣點；出生地點採預設城市清單（FR-036）

## UC-009 生成詳細分析

- **Actor**：CTX-ACTOR-002
- **對應 Story**：STORY-009
- **對應 Requirement**：FR-015, FR-016, FR-017, FR-018, FR-019, FR-022, FR-014, FR-038, FR-036

**Preconditions**

- 使用者已登入
- 點數餘額 ≥ 5 且未過期
- 已有星座與 MBTI 結果（血型、人類圖選填）

**Main Flow**

1. 使用者選擇生成詳細分析
2. 後端驗證登入、點數與用量限制 〔NFR-003, NFR-008〕
3. 後端將標籤、測驗結果與人類圖正規化為分析輸入並記錄資料版本
4. 後端原子扣 5 點並建立狀態為「生成中」的報告 〔NFR-017〕
5. 後端呼叫 AI 供應商，設定 Token 與逾時上限 〔NFR-008, NFR-009, NFR-002〕
6. 系統驗證報告含八章節、依據與不確定性標示，區分直接觀察與 AI 推測 〔NFR-013, NFR-007〕
7. 系統保存報告、模型名稱、提示詞版本與輸入版本，更新狀態為完成 〔NFR-015〕
8. 系統記錄 AI 用量與預估成本

**Alternate Flows**

- **點數不足或已過期**：拒絕並引導購買點數
- **缺少 MBTI 結果**：拒絕（422）並引導先完成 MBTI 測驗
- **超過頻率或用量限制**：拒絕並說明限制 〔NFR-008〕
- **AI 逾時或失敗**：依重試策略重試；仍失敗則狀態為失敗、返還已扣點並回報明確錯誤 〔NFR-009, NFR-011〕
- **輸出不符格式或含診斷式內容**：視為失敗，不交付、不扣點 〔NFR-007, NFR-013〕
- **並行重複請求**：僅建立一份報告、僅扣一次點 〔NFR-017〕

**Postconditions**

- 詳細分析保存 6 個月；點數已扣 5 點（失敗則返還）；用量已記錄

> 備註：非同步生成，逾時 120 秒視為失敗並返還點數（NFR-009）

## UC-010 購買點數

- **Actor**：CTX-ACTOR-001
- **對應 Story**：STORY-010
- **對應 Requirement**：FR-011, FR-013

**Preconditions**

- 使用者已登入
- 點數方案與價格已定義（定價待定）

**Main Flow**

1. 使用者於點數不足提示或點數頁選擇購買
2. 系統顯示點數用途、價格並明確告知不提供退款，使用者須勾選「同意立即提供數位內容、放棄解約」
3. 使用者確認，後端記錄同意（時間與條款版本）並建立付款流程 〔NFR-002, NFR-003〕
4. 使用者在付款服務完成付款
5. 付款結果由 UC-011 處理後入帳，系統顯示新餘額

**Alternate Flows**

- **未勾選同意**：不建立付款流程，提示須先同意
- **使用者取消付款**：不入帳，回到原頁面
- **付款失敗**：顯示失敗訊息，不入帳，可重試
- **訪客**：要求先登入
- **付款服務無法使用**：顯示明確錯誤 〔NFR-011〕

**Postconditions**

- 付款成功後點數增加；失敗則餘額不變

## UC-011 處理付款事件並入帳

- **Actor**：CTX-ACTOR-004（觸發：external-system）
- **對應 Story**：STORY-011
- **對應 Requirement**：FR-012, FR-013, FR-043

**Preconditions**

- 付款服務送出 webhook

**Main Flow**

1. 後端接收 webhook 並驗證簽章 〔NFR-004〕
2. 後端以事件 ID 檢查是否已處理（冪等） 〔NFR-004, NFR-017〕
3. 成功事件：原子地為使用者加點並記錄異動 〔NFR-017〕
4. 永久保存付款紀錄 〔NFR-005〕
5. 回應付款服務已接收

**Alternate Flows**

- **簽章無效**：拒絕並記錄安全事件 〔NFR-004〕
- **重複事件**：不重複加點，回應成功 〔NFR-004〕
- **付款失敗事件**：記錄失敗，不加點
- **無法對應使用者或入帳失敗**：記錄並通知營運處理，不遺失付款紀錄 〔NFR-011〕

**Postconditions**

- 點數依付款結果變動；付款紀錄於帳號存續期間永久保存

> 備註：觸發者為付款服務（CTX-EXT-001），營運人員（CTX-ACTOR-004）負責異常處理

## UC-021 以點數將詳細分析報告書寄送 email

- **Actor**：CTX-ACTOR-002
- **對應 Story**：STORY-021
- **對應 Requirement**：FR-034, FR-038, FR-014, FR-042

**Preconditions**

- 使用者已登入且帳號有 email
- 報告已生成且未到期
- 點數餘額 ≥ 1

**Main Flow**

1. 使用者選擇一份詳細分析並選擇下載報告書
2. 後端驗證請求者為報告擁有者 〔NFR-003〕
3. 後端檢查此報告是否曾下載；若曾下載，系統提醒並顯示上次下載時間，須使用者確認才繼續

- **非擁有者請求**：拒絕存取 〔NFR-003〕
